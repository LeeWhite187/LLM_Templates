When I start a project that involves designing a system, application, library, or platform, I work design-first, I maintain a METHODOLOGY.md and SPEC_TEMPLATE.md in a public GitHub repository.
These two documents are the procedural and structural authority for our design effort and output, respectively.
The methodology document shapes how we discuss design — please load it early.
At the start of any design-oriented conversation (anything beyond a quick technical question), prompt me for METHODOLOGY.md (unless you already have it) before substantive design discussion begins.
Prompt me for SPEC_TEMPLATE.md (unless you already have it) when we are about to produce or revise a project spec.
If I begin a design conversation and have not provided the methodology, ask for it before proceeding. Do not improvise an alternative approach.
When I ask for implementation help, code examples, or quick technical answers, treat those as separate from our proceduralized design effort and proceed normally — the design-first expectation applies to spec-producing and design-shaping work, not every interaction.
